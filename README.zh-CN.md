# replacing-legacy-systems（系统替换）

这是一个 [Agent Skill](https://agentskills.io/specification)，用来替换一个还在运行、有真实数据和用户的系统。重建、重写、“系统升级”、迁移都适用。

## 为什么要有它

AI 写代码以后，“建”本身不慢了。替换卡住的地方变成两类：

- **旧系统的事实发现得太晚**：某张表其实从 2021 年才开始有数据；某个以为有的数字，其实从来没存过。
- **定好的决定被重新打开**：当初没写下这个决定依赖什么前提，前提一变，就得从头再争一次。

现有的迁移 skill 大多讲代码翻译、绞杀者模式和分批放量。这些基础模型本来就会，这个 skill 补的是它们没讲的部分。

## 模型

从旧楼带走三样东西：

| 带走 | 是什么 |
|---|---|
| **用途** | 用户实际拿它做什么。这决定了你建的是一栋楼，而不是一座桥。 |
| **病历** | 遇到过、但一直没解决的问题。反复出现的手工修补，就是没写下来的 bug 报告。 |
| **原料** | 无法重新生成的数据和采集流。靠测量来验收，不靠描述。 |

**平面图**留下不带：旧表结构、定时任务的布局、服务怎么拆、公式怎么写。它们只当作证据，不当作规格。

用这三样写一份可检查的**标准**，再按标准从零开始建。每一块先选一种做法：

- **照旧**：新块的输出要和旧系统一致，旧系统就是标准答案。
- **重做**：动工前先说清楚，拿什么来判对错。

以上所有内容都记进一本**台账**（`ledger-template.md`）。每一行写清楚：测了什么、这个结论依赖什么前提、看到什么情况要重开它。问题晚到时，只重开受影响的那一行。

## 安装

把 `skills/replacing-legacy-systems/` 复制到 agent 的 skills 目录：

- Claude Code：`~/.claude/skills/`（个人）或 `.claude/skills/`（项目）
- Codex、Copilot CLI、Gemini CLI：`~/.agents/skills/`

## 证据

`tests/` 里是开发这个 skill 时用的场景，以及不加载和加载 skill 时的回答对比，详见 `tests/results.md`。

以上结果由 skill 作者自己打分，每个场景只跑了一次，还没有做独立的盲评。

不加载 skill 时，agent 已经会做并行比对，也会把事故变成测试。加载以后多出四件事：

- 每份数据都测出可信区间
- 每条需求都能追溯到一个真实用途或病历
- 每个决定都写下前提和反证
- 每个重做的块都在动工前说清楚拿什么判对错
